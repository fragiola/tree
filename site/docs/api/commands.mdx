The model runs 27 commands. Each one takes a JSON payload, checked against its JSON Schema, and returns a `CommandResult`: `{ ok: true, value }`, or `{ ok: false, error }`. Run one with `model.run(name, payload)` (typed by your registry), or give it as untrusted JSON to `model.dispatch({ command, payload })`, which validates it first. `model.get("commands")` returns this same list with the schemas, ready to become tool definitions for an assistant.

Every command can return `invalid_payload` (the payload does not match its schema, with the path of each problem), `vetoed` (a middleware refused it), `queued` (a middleware ran it while another command was running) and `middleware_error`; each command lists the ones its own rules add: `not_found` (an item it names is missing) and `refused` (a rule of the tree refuses the change).

The payload types below use `T`, your registry: an item's `data` is checked against its `kind`.

## Batches

### `batch`

Run several commands as one step: they apply in order, each seeing the result of the ones before it, and either all of them apply (one event, one undo step) or none does (the first failure is returned, at its path in `commands`).

It may run as a step of a continuous gesture: `model.run(…, { transient: true })`.

**Payload** (`{ commands: BatchEntry<T>[] }`)

| field | type | required | description |
| --- | --- | --- | --- |
| `commands` | `object[]` | yes | the commands, in order |

**Result** (`{ results: unknown[] }`)

| field | type | required | description |
| --- | --- | --- | --- |
| `results` | `JSON[]` | yes | each command's value, in order |

**Errors**: those of the commands it runs (the first failure, at its path in `commands`); nothing applies unless all succeed.

```ts
model.run("batch", {
    commands: [
        {
            command: "item.expand",
            payload: {
                itemId: "src"
            }
```
