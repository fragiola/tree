title: Known limitations
description: What the first release does not do yet - virtualization, drags between trees, foreign drops - and what stays yours by design.
---

The first release covers a tree view's behaviour end to end, but not everything a tree can do.
Here is what it leaves out, on purpose or for a later release.

## Not in this release

- **No virtualization.** Every visible item is rendered. Trees of a few thousand visible rows are
  fine; beyond that, collapse by default or load children on demand
  ([Async loading](/docs/guides/async-loading)). `model.get("visible-items")` is already the flat
  render order a virtualizer needs, so adding one later will not break the API.
- **No drag between two trees.** A drag moves items inside its own tree; two trees, even over
  one model, do not exchange items by dragging. Move them with `item.remove` and `item.add`.
- **No foreign drops.** Files from the desktop, links, text or another library's elements cannot
  be dropped on a tree, and a tree's items cannot be dropped elsewhere: the drag uses Pointer
  Events, not native HTML5 drag and drop.
- **No built-in app policy.** Undo and redo, persistence, translations and announcement text are
  yours: the examples show each one as code to copy.
- **React, Vue and Angular.** Another framework needs an adapter of its own, over the same core
  (`@fragiola/tree`).

Found something else? [Open an issue](https://github.com/fragiola/tree/issues).
