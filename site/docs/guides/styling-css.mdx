---
title: Styling with plain CSS
description: Style every part with class names and attribute selectors on the state the primitives expose - no build step, no framework, no overrides to fight.
---

The primitives render plain elements with no styles of their own, so there is nothing to
override: give each part a class name and select on its state attributes. Everything below is
ordinary CSS.

## A complete stylesheet

## Why the row, not the item

The item's element holds its row **and** its group of children. A style on `.tree-item` (a
background, a hover) would cover the whole subtree, and `[data-selected]` on an item would match
its descendants through a descendant selector. Every part carries its own item's state, so style
the row with its own attributes, and only the focus ring through the item
(`.tree-item:focus-visible > .tree-row`).

## Selecting on state

Every attribute is present or absent, never `"false"`, so the plain attribute selector is the
whole test: `[data-expanded]`, `[data-checked]`, `[data-indeterminate]`, `[data-loading]`,
`[data-drop-target][data-drop-position="inside"]`. ARIA works too: `[aria-expanded="true"]`.
The full list is on [State attributes](/docs/concepts/state-attributes).

## Motion

A group is unmounted while its item is collapsed (in Angular, its element stays, empty and
hidden with `display: none`). To animate the opening, keep it mounted with
`keepMounted` (it is then hidden with `display: none` when collapsed), or animate its entry with
`@starting-style`:

```css
[data-tree-part="group"] {
    transition: opacity 150ms;
    @starting-style {
        opacity: 0;
    }
}
```
