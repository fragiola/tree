---
title: Inline rename
description: Edit an item's label in place with Tree.RenameInput, validate the new name with middleware, and show why a name was refused.
---

Renaming is a short-lived model state: `item.start-rename` (F2 on the focused item) makes an
item the **renaming** item, `item.rename` sets its label and ends it, `item.cancel-rename` ends it
unchanged. `Tree.RenameInput` is the text field, rendered only while its item is renaming; the
rules for a good name are yours.

## The input

Put it in the row, next to (or instead of) the label, and name it:

<Framework name="react">

```tsx
function FileItem({ item }: { item: ItemOf<Types> }) {
    return (
        <Tree.Item item={item}>
            <Tree.ItemContent className="row">
                <Tree.Toggle>▸</Tree.Toggle>
                <span className="label">{item.label}</span>
                <Tree.RenameInput aria-label={`Rename ${item.label}`} className="rename" />
            </Tree.ItemContent>
            <Tree.Group<Types>>{(child) => <FileItem item={child} />}</Tree.Group>
        </Tree.Item>
    );
}
```

</Framework>

<Framework name="vue">

```vue title="file-item.vue"
<script setup lang="ts">
import type { ItemOf } from "@fragiola/tree-vue";
import { Tree, type Types } from "./tree";

defineProps<{ item: ItemOf<Types> }>();
</script>

<template>
    <Tree.Item :item="item">
        <Tree.ItemContent class="row">
            <Tree.Toggle>▸</Tree.Toggle>
            <span class="label">{{ item.label }}</span>
            <Tree.RenameInput :aria-label="`Rename ${item.label}`" class="rename" />
        </Tree.ItemContent>
        <Tree.Group v-slot="{ item: child }">
            <FileItem :item="child" />
        </Tree.Group>
    </Tree.Item>
</template>
```

</Framework>

<Framework name="angular">

```html
<ng-template [treeItems]="model" let-item>
    <div [treeItem]="item">
        <div treeItemContent class="row">
            <span treeToggle>▸</span>

        </div>

    </div>

```

The input element stays in the row, hidden (`display: none`) while its item is not renaming.

</Framework>

```css
.row[data-renaming] .label {
    display: none;
}
```

It opens with the label, focused and selected. Enter commits and Escape cancels, and focus goes
back to the item; leaving the field commits (or cancels, when the name is refused) and leaves
focus where it went.

## Starting a rename

F2 renames the focused item (rebind it with `keyMap.rename`). From a button, a menu or a double
click, run the command:

<Framework name="react">

```tsx
const { model } = useTree<Types>();

<Tree.ItemContent onDoubleClick={() => model.run("item.start-rename", { itemId: item.id })}>
    {item.label}
</Tree.ItemContent>;
```

</Framework>

<Framework name="vue">

```vue
<script setup lang="ts">
const { model } = useTree<Types>();
</script>

<template>
    <Tree.ItemContent @dblclick="model.run('item.start-rename', { itemId: item.id })">
        {{ item.label }}
    </Tree.ItemContent>
</template>
```

</Framework>

<Framework name="angular">

```html
<div treeItemContent (dblclick)="model.run('item.start-rename', { itemId: item.id })">
    {{ item.label }}
</div>
```

</Framework>

It is refused for a disabled item and for one that is not `renamable` (on the item, or
`settings.renamable` for all of them).

## Validating the name

The label is never empty (the command's schema). Every other rule is a middleware, which sees
each `item.rename`, from the input or from code, and can veto it or rewrite its payload:

```ts
import { veto } from "@fragiola/tree-react";

model.use((ctx, next) => {
    if (ctx.command !== "item.rename") return next();
    const label = ctx.payload.label.trim();
    if (label.includes("/")) return veto("A name cannot contain “/”.");
    const parent = ctx.get("item-parent-by", { itemId: ctx.payload.itemId });
    const siblingIds = parent ? (parent.childItemIds ?? []) : ctx.state.rootItemIds;
    const taken = siblingIds.some(
        (id) => id !== ctx.payload.itemId && ctx.get("item-by", { id })?.label === label,
    );
    if (taken) return veto(`“${label}” is already in this folder.`);
    ctx.payload = { ...ctx.payload, label }; // save the trimmed name
    return next();
});
```

## Showing why

A refused commit keeps the input open with `aria-invalid` and `data-invalid`, and calls
`onRenameError` (`@rename-error` in Vue, `(renameError)` in Angular) with the error. Its state (for `className` and
`render`) has `invalid` and `error`:

<Framework name="react">

```tsx
const [error, setError] = useState<string>();

<Tree.RenameInput
    aria-label={`Rename ${item.label}`}
    aria-describedby={error ? errorId : undefined}
    onRenameError={(failure) => setError(failure.message)}
    onChange={() => setError(undefined)}
    className={(state) => (state.invalid ? "rename rename-invalid" : "rename")}
/>;
{error && <span id={errorId} role="alert">{error}</span>}
```

</Framework>

<Framework name="vue">

```vue
<script setup lang="ts">
import { ref } from "vue";

const error = ref<string>();
</script>

<template>
    <Tree.RenameInput
        :aria-label="`Rename ${item.label}`"
        :aria-describedby="error ? errorId : undefined"
        class="rename"
        @rename-error="(failure) => (error = failure.message)"
        @input="error = undefined"
    />
    <span v-if="error" :id="errorId" role="alert">{{ error }}</span>
</template>
```

A class has no function form in Vue: style the refused state with `.rename[data-invalid]`, or
read `invalid` and `error` from the `render` slot's `state`.

</Framework>

<Framework name="angular">

```html
<input
    treeRenameInput
    #rename="treeRenameInput"
    [attr.aria-label]="'Rename ' + item.label"
    [attr.aria-describedby]="error() ? errorId : null"
    class="rename"
    [class.rename-invalid]="rename.state().invalid"
    (renameError)="error.set($event.message)"
    (input)="error.set(undefined)"
/>
@if (error()) {
    <span [id]="errorId" role="alert">{{ error() }}</span>
}
```

`error` is a signal of the component (`signal<string | undefined>(undefined)`); the input's own
`state()` has `invalid` and `error` too.

</Framework>
