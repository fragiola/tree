---
title: Async loading
description: Load a parent's children the first time it is expanded, show the loading and error states, retry a failed load and refresh loaded children.
---

A parent whose children come from your server has a `childrenStatus` instead of
`childItemIds`. The first time it is expanded and visible, the engine calls your
`loadChildren(item, { signal })` and gives the model what it returns. The package makes no network
call: the fetch, the cache and the error message are yours.

## Marking the parents

```ts
const json: TreeJson<Types> = {
    version: 1,
    rootItemIds: ["photos", "documents"],
    items: {
        photos: { kind: "folder", label: "Photos", childrenStatus: "unloaded" },
        documents: { kind: "folder", label: "Documents", childrenStatus: "unloaded" },
    },
};
```

The status is `unloaded` (never asked), `loading`, `loaded` or `error`. A child that is a parent
itself gets a `childrenStatus` too, and loads when it is expanded.

## The loader

`loadChildren` returns the children as item JSON (`TreeItemJson<Types>[]`); an item without an
`id` gets one from the model. Pass `signal` to `fetch`: the engine aborts a load when the tree
unmounts, and an aborted or stale load changes nothing.

<Framework name="react">

```tsx
import { type LoadChildren, Tree, type TreeItemJson } from "@fragiola/tree-react";

const loadChildren: LoadChildren<Types> = async (item, { signal }) => {
    const response = await fetch(`/api/folders/${item.id}/children`, { signal });
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    return (await response.json()) as TreeItemJson<Types>[];
};

export function Drive() {
    return (
        <Tree.Root<Types> defaultTree={json} loadChildren={loadChildren} aria-label="Cloud drive">
            <Tree.Items<Types>>{(item) => <DriveItem item={item} />}</Tree.Items>
            <Tree.LiveRegion className="visually-hidden" />
        </Tree.Root>
    );
}
```

</Framework>

```ts title="drive.ts"
import { Component } from "@angular/core";
import { createTreeModel, type LoadChildren, TREE, type TreeItemJson } from "@fragiola/tree-angular";
import { json, type Types } from "./tree";

@Component({
    selector: "app-drive",
    imports: [TREE],
    template: `
        <div [treeRoot]="model" [loadChildren]="loadChildren" aria-label="Cloud drive">
            <ng-template [treeItems]="model" let-item>
                <div [treeItem]="item">
                    <div treeItemContent>{{ item.label }}</div>
                    <div treeGroup></div>
                </div>
            </ng-template>
            <div treeLiveRegion class="visually-hidden"></div>
        </div>
    `,
})
export class Drive {
    protected readonly model = createTreeModel<Types>(json);
    protected readonly loadChildren: LoadChildren<Types> = async (item, { signal }) => {
        const response = await fetch(`/api/folders/${item.id}/children`, { signal });
        if (!response.ok) throw new Error(`HTTP ${response.status}`);
        return (await response.json()) as TreeItemJson<Types>[];
    };
}
```

</Framework>

The engine runs the commands around it (`item.set-children-status` to `loading`, then
`item.set-children`, or `item.set-children-status` to `error`), so your middleware and listeners
see a load like any other change.

## Loading and error states

While loading, the item carries `aria-busy` and every part `data-loading`; after a failure,
`data-load-error`. Show a spinner, or an error with a retry button, from the item's status:

<Framework name="react">

```tsx
import { type ItemOf, Tree, useTree, useTreeState } from "@fragiola/tree-react";

function DriveItem({ item }: { item: ItemOf<Types> }) {
    const { engine } = useTree<Types>();
    const status = useTreeState<Types, string | undefined>((_state, model) =>
        model.get("children-status-by", { itemId: item.id }),
    );
    return (
        <Tree.Item item={item}>
            <Tree.ItemContent className="row">
                <Tree.Toggle>▸</Tree.Toggle>
                <span>{item.label}</span>
                {status === "loading" && <Spinner aria-hidden />}
                {status === "error" && (
                    <button
                        type="button"
                        aria-label={`Retry loading ${item.label}`}
                        onClick={() => engine.run("load-children", { itemId: item.id })}
                    >
                        Retry
                    </button>
                )}
            </Tree.ItemContent>
            <Tree.Group<Types>>{(child) => <DriveItem item={child} />}</Tree.Group>
        </Tree.Item>
    );
}
```

</Framework>

<Framework name="vue">

```vue title="drive-item.vue"
<script setup lang="ts">
import { type ItemOf, useTree, useTreeState } from "@fragiola/tree-vue";
import { Tree, type Types } from "./tree";

const props = defineProps<{ item: ItemOf<Types> }>();
const { engine } = useTree<Types>();
// the selector reads the prop: it selects again when the item changes
const status = useTreeState<Types, string | undefined>((_state, model) =>
    model.get("children-status-by", { itemId: props.item.id }),
);
</script>

<template>
    <Tree.Item :item="item">
        <Tree.ItemContent class="row">
            <Tree.Toggle>▸</Tree.Toggle>
            <span>{{ item.label }}</span>
            <Spinner v-if="status === 'loading'" aria-hidden="true" />
            <button
                v-if="status === 'error'"
                type="button"
                :aria-label="`Retry loading ${item.label}`"
                @click="engine.run('load-children', { itemId: item.id })"
            >
                Retry
            </button>
        </Tree.ItemContent>
        <Tree.Group v-slot="{ item: child }">
            <DriveItem :item="child" />
        </Tree.Group>
    </Tree.Item>
</template>
```

</Framework>

<Framework name="angular">

The item's `state()`, through `#node="treeItem"`, has `loading` and `loadError`, and the root's
`engine`, through `#tree="treeRoot"`, loads again:

```html
<div [treeRoot]="model" #tree="treeRoot" [loadChildren]="loadChildren" aria-label="Cloud drive">
    <ng-template [treeItems]="model" let-item>
        <div [treeItem]="item" #node="treeItem">
            <div treeItemContent class="row">
                <span treeToggle>▸</span>
                <span>{{ item.label }}</span>
                @if (node.state().loading) {
                    <svg lucideLoaderCircle aria-hidden="true"></svg>
                }
                @if (node.state().loadError) {
                    <button
                        type="button"
                        [attr.aria-label]="'Retry loading ' + item.label"
                        (click)="tree.engine.run('load-children', { itemId: item.id })"
                    >
                        Retry
                    </button>
                }
            </div>
            <div treeGroup></div>
        </div>
    </ng-template>
</div>
```

</Framework>

`engine.run("load-children", { itemId })` loads again (a retry, or a first load without
expanding); it is refused while the item is loading. A failed load is announced through your
`announce` (an event of type `load-error`, with the `itemId` and the `error`):

```ts
const announce = (event: AnnounceEvent) =>
    event.type === "load-error" ? "Could not load this folder. Use Retry to try again." : undefined;
```

## Refreshing

`item.reset-children` forgets an item's loaded children (and everything inside them): the status
goes back to `unloaded`, and the next expand loads again; when the item is expanded, the engine
loads it right away.

```ts
model.run("item.reset-children", { itemId: "photos" });
```

To put children in yourself (from a cache, a push from the server), run `item.set-children` with
the items.

## Saving a tree that loads

A `loading` item is saved as `unloaded`: a load is never part of the document, and the next
engine starts it again. Loaded children are saved like any others.
