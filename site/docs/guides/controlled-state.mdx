---
title: Controlled state
description: Own the expanded, selected and checked items in your app state, decide what each change becomes, and keep the tree in step with your app.
---

<Framework name="react">

By default the model owns its state, and you read it with `useTreeState`. When your app wants to
own a list (to sync it with the URL, a store or another view), the root takes it as a controlled
prop, with a callback for every change the tree would make:

| prop | callback |
| --- | --- |
| `expandedItemIds` | `onExpandedItemIdsChange` |
| `selectedItemIds` | `onSelectedItemIdsChange` |
| `checkedItemIds` | `onCheckedItemIdsChange` |

Each pair is independent: control the selection and leave the expansion to the model.

</Framework>

<Framework name="vue">

By default the model owns its state, and you read it with `useTreeState`. When your app wants to
own a list (to sync it with the URL, a store or another view), bind it with `v-model` on the
root: the tree reports every change it would make through the list's `update:` event.

| `v-model` | event |
| --- | --- |
| `v-model:expanded-item-ids` | `update:expandedItemIds` |
| `v-model:selected-item-ids` | `update:selectedItemIds` |
| `v-model:checked-item-ids` | `update:checkedItemIds` |

Each list is independent: control the selection and leave the expansion to the model.

</Framework>

## Controlling the expansion

<Framework name="react">

```tsx
import { Tree } from "@fragiola/tree-react";
import { useState } from "react";

export function Outline() {
    const [expandedItemIds, setExpandedItemIds] = useState<string[]>(["src"]);
    return (
        <>
            <button type="button" onClick={() => setExpandedItemIds([])}>
                Collapse all
            </button>
            <Tree.Root<Types>
                defaultTree={json}
                expandedItemIds={expandedItemIds}
                onExpandedItemIdsChange={setExpandedItemIds}
                aria-label="Outline"
            >
                <Tree.Items<Types>>{(item) => <OutlineItem item={item} />}</Tree.Items>
            </Tree.Root>
        </>
    );
}
```

</Framework>

<Framework name="vue">

```vue title="outline.vue"
<script setup lang="ts">
import { ref } from "vue";
import OutlineItem from "./outline-item.vue";
import { json, Tree } from "./tree";

const expandedItemIds = ref<string[]>(["src"]);
</script>

<template>
    <button type="button" @click="expandedItemIds = []">Collapse all</button>
    <Tree.Root
        :default-tree="json"
        v-model:expanded-item-ids="expandedItemIds"
        aria-label="Outline"
    >
        <Tree.Items v-slot="{ item }"><OutlineItem :item="item" /></Tree.Items>
    </Tree.Root>
</template>
```

</Framework>

## Deciding what a change becomes

<Framework name="react">

The callback receives the list the tree would have; the prop decides what it has. A change the
app does not accept is reverted: here a pinned folder stays open.

```tsx
const change = (itemIds: string[]) =>
    setExpandedItemIds(itemIds.includes("src") ? itemIds : ["src", ...itemIds]);

<Tree.Root<Types>
    defaultTree={json}
    expandedItemIds={expandedItemIds}
    onExpandedItemIdsChange={change}
    aria-label="Outline"
>
    <Tree.Items<Types>>{(item) => <OutlineItem item={item} />}</Tree.Items>
</Tree.Root>;
```

</Framework>

<Framework name="vue">

The event carries the list the tree would have; the prop decides what it has. Split the
`v-model` into the prop and the event to decide: a change the app does not accept is reverted,
here a pinned folder stays open.

```vue
<script setup lang="ts">
const change = (itemIds: string[]) => {
    expandedItemIds.value = itemIds.includes("src") ? itemIds : ["src", ...itemIds];
};
</script>

<template>
    <Tree.Root
        :default-tree="json"
        :expanded-item-ids="expandedItemIds"
        @update:expanded-item-ids="change"
        aria-label="Outline"
    >
        <Tree.Items v-slot="{ item }"><OutlineItem :item="item" /></Tree.Items>
    </Tree.Root>
</template>
```

</Framework>

## How it works

Controlled props are commands too. When a prop differs from the model, the root runs the commands
that bring the model to it (`item.expand`, `item.collapse`, `tree.select`, `item.check`), as one
batch, before the tree shows it (before paint in React, before mount and after each change of the
prop in Vue), with `meta.source` set to `"controlled"`; those commits report no change. Every other
commit that changes a list reports the new list (`onExpandedItemIdsChange` and the other callbacks
in React, the `update:*` events in Vue). So:

- your middleware sees the controlled changes too, and can tell them apart by their `meta`;
- an id the tree does not have is skipped rather than failing the rest (an expansion or a check
  the model refuses, a disabled item's, is skipped too);
- in cascade mode, `checkedItemIds` is normalized by the model (checking a parent checks its
  children), so the list you get back may hold more ids than you set.

## When not to control

Controlled props are for state the app shares. To read the state, `useTreeState` is enough; to
change it from a button, run a command (`model.run("tree.collapse-all", {})`); to save it, the
document holds all of it ([Saving and restoring](/docs/guides/persistence)).
