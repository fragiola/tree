The tree splits cleanly into what needs a screen and what does not, and the tests can follow the
same line: the model's rules in plain Node, the component through its roles, and the browser
for the gestures.

## The model, in plain Node

The model needs no DOM. Load a document, run the commands your feature runs, and assert the
state and the results:

```ts title="files.test.ts"
import { createTreeModel } from "@fragiola/tree";
import { expect, it } from "vitest";
import { json, type Types } from "./files";
import { namingRules } from "./naming-rules";

it("refuses a name already taken in the folder", () => {
    const model = createTreeModel<Types>(json);
    namingRules(model);
    const result = model.run("item.rename", { itemId: "app", label: "main.tsx" });
    expect(result.ok).toBe(false);
    expect(model.get("item-by", { id: "app" })?.label).toBe("app.tsx");
});

it("moves the selection into a folder", () => {
    const model = createTreeModel<Types>(json);
    model.run("tree.select", { itemIds: ["readme"] });
    expect(model.can("item.move", { itemIds: ["readme"], to: { parentItemId: "src", index: 0 } })).toBe(true);
});
```

`model.check` returns the error a refusal would have, without changing anything, which makes
permission tests one line each.

## The component, with Testing Library

The tree is reachable by role and name, like any accessible widget. A tree ref gives the test the
model and the engine:

<Framework name="react">

```tsx title="file-tree.test.tsx"
import { createTreeRef, Tree } from "@fragiola/tree-react";
import { act, fireEvent, render, screen } from "@testing-library/react";
import { expect, it } from "vitest";

it("expands a folder with ArrowRight", () => {
    const tree = createTreeRef<Types>();
    render(
        <Tree.Root<Types> defaultTree={json} treeRef={tree} aria-label="Files">
            <Tree.Items<Types>>{(item) => <FileItem item={item} />}</Tree.Items>
        </Tree.Root>,
    );
    const src = screen.getByRole("treeitem", { name: "src" });
    act(() => src.focus());
    fireEvent.keyDown(src, { key: "ArrowRight" });
    expect(src).toHaveAttribute("aria-expanded", "true");
    expect(tree.current?.model.is("item-expanded", { itemId: "src" })).toBe(true);
});
```

</Framework>

<Framework name="vue">

```ts title="file-tree.test.ts"
import { createTreeRef, type ItemOf } from "@fragiola/tree-vue";
import { fireEvent, render, screen } from "@testing-library/vue";
import { expect, it } from "vitest";
import { h } from "vue";
import { Tree } from "./tree"; // typedTree<Types>()

it("expands a folder with ArrowRight", async () => {
    const tree = createTreeRef<Types>();
    render(() =>
        h(Tree.Root, { defaultTree: json, treeRef: tree, "aria-label": "Files" }, () =>
            h(Tree.Items, null, {
                default: ({ item }: { item: ItemOf<Types> }) => h(FileItem, { item }),
            }),
        ),
    );
    const src = screen.getByRole("treeitem", { name: "src" });
    src.focus();
    await fireEvent.keyDown(src, { key: "ArrowRight" });
    expect(src).toHaveAttribute("aria-expanded", "true");
    expect(tree.value?.model.is("item-expanded", { itemId: "src" })).toBe(true);
});
```

Render an SFC of your own (`render(FileTree)`) the same way; `fireEvent` returns a promise that
resolves once Vue has updated the DOM.

</Framework>

<Framework name="angular">

```ts title="file-tree.spec.ts"
import { Component, viewChild } from "@angular/core";
import { TREE, TreeRootDirective } from "@fragiola/tree-angular";
import { fireEvent, render, screen } from "@testing-library/angular";
import { expect, it } from "vitest";
import { json } from "./files";

@Component({
    imports: [TREE],
    template: `
        <div treeRoot [defaultTree]="json" aria-label="Files">
            <ng-template [treeItems]="json" let-item>
                <div [treeItem]="item" [attr.aria-label]="item.label">
                    <div treeItemContent>{{ item.label }}</div>
                    <div treeGroup></div>
                </div>
            </ng-template>
        </div>
    `,
})
class FileTree {
    protected readonly json = json;
    readonly tree = viewChild.required(TreeRootDirective);
}

it("expands a folder with ArrowRight", async () => {
    const { fixture } = await render(FileTree);
    const src = screen.getByRole("treeitem", { name: "src" });
    src.focus();
    fireEvent.keyDown(src, { key: "ArrowRight" });
    await fixture.whenStable();
    expect(src).toHaveAttribute("aria-expanded", "true");
    const { model } = fixture.componentInstance.tree();
    expect(model().is("item-expanded", { itemId: "src" })).toBe(true);
});
```

The root's handle, `viewChild(TreeRootDirective)`, gives the test the model and the engine.

</Framework>

Give each item an `aria-label` of its own label when it has children, so its name is not its
children's text too ([Accessible names](/docs/getting-started/accessible-names)).

## The browser, with Playwright

Drags, scrolling and focus rings need a real browser. Reach items by role and name, and by their
path (`data-tree-path`) when two share a label; reach a row by its part:

```ts title="file-tree.spec.ts"
import { expect, test } from "@playwright/test";

test("drags README.md into src", async ({ page }) => {
    await page.goto("/files");
    const tree = page.getByRole("tree", { name: "Files" });
    const readme = tree.getByRole("treeitem", { name: "README.md" });
    const src = tree.locator('[data-tree-path="/0"] > [data-tree-part="content"]');
    await readme.locator('[data-tree-part="content"]').dragTo(src);
    await expect(tree.locator('[data-tree-path="/0/0"]')).toHaveAccessibleName("README.md");
});
```

Pointer Events drags work with Playwright's mouse; a drag starts after the press moves past
`dragThreshold` (4 pixels by default), which `dragTo` does. To test a drag without a pointer,
use the keyboard drag (Ctrl+Shift+D, the arrows, Enter).

## Never by class name

Select by roles, names, `data-tree-part`, `data-tree-path` and the state attributes, never by
your class names: the styles can change and the tests stay green
([Parts and paths](/docs/concepts/parts-and-paths)).
