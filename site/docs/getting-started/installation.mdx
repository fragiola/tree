## Requirements

| requirement | why |
| --- | --- |
| `react` and `react-dom` **^19** (React) | peer dependencies of `@fragiola/tree-react`. The primitives use React 19 features: `ref` as a plain prop and ref cleanup functions. |
| `vue` **^3.5** (Vue) | the peer dependency of `@fragiola/tree-vue`. The primitives are render functions: no compiler plugin is needed beyond your app's own. |
| `@angular/core` **^22** (Angular) | the peer dependency of `@fragiola/tree-angular`. Standalone directives built on signals: no NgModule, and no zone.js (zoneless is Angular's default). |
| A browser DOM | the engine focuses elements, listens to Pointer Events and measures rows during a drag. The **model** runs in plain Node (tests, server-side JSON handling), but a tree is interactive only on the client. |
| ES modules | every package is ESM only (`"type": "module"`; the Angular package in the Angular Package Format). |

`@fragiola/tree` has **zero runtime dependencies**, and each adapter (`@fragiola/tree-react`,
`@fragiola/tree-vue`, `@fragiola/tree-angular`) depends only on the core, at the exact same version, and on its framework.

Every package ships its types and is best used with TypeScript in `strict` mode: the document,
the command payloads and each item's data are typed by your registry
([Typed data](/docs/concepts/typed-data)). Plain JavaScript works too: the model validates every
command's payload at run time either way.

## What to import from where

<Framework name="react">

Everything comes from `@fragiola/tree-react`:

```tsx
import {
    // the primitives (one namespace) and the hooks
    Tree,
    useTree,
    useTreeState,
    // the core: the model, its types and helpers
    createTreeModel,
    type ItemOf,
    type TreeJson,
} from "@fragiola/tree-react";
```

The React package re-exports the whole core (`createTreeModel`, `TreeModel`, `TreeJson`, `ItemOf`,
`Middleware`, `veto`, `createTreeEngine`, `DEFAULT_KEY_MAP`, …), so the pages on
[the core API](/docs/api/model) apply as they are: in a React app, import those names from
`@fragiola/tree-react` too.

</Framework>

<Framework name="vue">

Everything comes from `@fragiola/tree-vue`:

```ts
import {
    // the primitives (one namespace), typed by your registry, and the composables
    typedTree,
    useTree,
    useTreeState,
    // the core: the model, its types and helpers
    createTreeModel,
    type ItemOf,
    type TreeJson,
} from "@fragiola/tree-vue";
```

The Vue package re-exports the whole core (`createTreeModel`, `TreeModel`, `TreeJson`, `ItemOf`,
`Middleware`, `veto`, `createTreeEngine`, `DEFAULT_KEY_MAP`, …), so the pages on
[the core API](/docs/api/model) apply as they are: in a Vue app, import those names from
`@fragiola/tree-vue` too. [Vue primitives](/docs/api/vue) maps each React prop of the API pages
onto Vue.

</Framework>

## Without a framework

The core is published on its own as `@fragiola/tree`, for code that renders nothing: handling tree
JSON on a server, a script or a test that runs no framework, or an adapter for another framework.

```sh
pnpm add @fragiola/tree
```

```ts
import { createTreeModel, type TreeJson } from "@fragiola/tree";
```

An app never needs it: it comes with its adapter.

## Server rendering

The primitives render on the server: `Tree.Root` outputs the tree's markup with its roles and
state, and creates its engine (focus, keys, drags, the loader) only once it is mounted in the
browser. A server render neither subscribes to the model nor changes it.

<Framework name="react">

In Next.js, the file that renders the tree is a client component:

```tsx title="app/files/file-tree.tsx"
"use client";

import { Tree, type TreeJson } from "@fragiola/tree-react";

type Types = { items: { folder: undefined; file: undefined } };

export function FileTree({ json }: { json: TreeJson<Types> }) {
    return (
        <Tree.Root<Types> defaultTree={json} aria-label="Files">
            <Tree.Items<Types>>
                {(item) => (
                    <Tree.Item item={item}>
                        <Tree.ItemContent>{item.label}</Tree.ItemContent>
                    </Tree.Item>
                )}
            </Tree.Items>
        </Tree.Root>
    );
}
```

</Framework>

<Framework name="vue">

In Nuxt, the tree renders on the server as it is, and takes over in the browser: no directive is
needed. A model shared by every request (created in a module) is never changed by a server render.

</Framework>

<Framework name="angular">

With Angular's server rendering, the tree renders on the server as it is, and takes over in the
browser: the root creates its engine after its first render there (`afterNextRender`). A model
shared by every request (created in a module) is never changed by a server render.

</Framework>
